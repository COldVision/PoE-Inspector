# Пайплайн: адаптация всех разделов референс-сайт в нашу базу данных

Цель: приложение-база, у которого есть все разделы референс-сайт **и больше**: 3D-модели, анимации, звуки, экспорт в Blender, запись, редактор персонажа, работа напрямую с файлами игры.

## 0. Принципы

1. **Источник данных — файлы игры, а не сайт.** У нас уже есть чтение Bundles2 и 1023 таблиц `data/balance/*.datc64` (217 из них есть на русском в `data/balance/russian/`). Сайт используется только как **спецификация** (какие разделы, какие колонки и фильтры) и как **эталон для проверки** (счётчики записей, названия). Тексты, картинки и вёрстку сайта не копируем.
2. **Один универсальный слой, много страниц.** Не пишем 40 отдельных парсеров: общий загрузчик таблиц + описание «раздела» (какие таблицы, какие связи, какие колонки, какие фильтры) → страницы строятся из описания.
3. **Наше преимущество встраивается в каждую сущность:** у предмета — 3D-модель и экипировка на персонаже, у умения — анимация, звук и эффект удара, у монстра — анимации, озвучка, оружие, у NPC — модель в редакторе.
4. **Русский и английский всегда вместе** (RU из `russian/`, EN из основных таблиц).
5. **Каждый раздел принимается по счётчикам**: число записей у нас ≥ числа на сайте (с учётом скрытого на сайте).

## 2. Стадии пайплайна

### P0. Обход сайта как спецификации (1 раз)
- Скрипт обходит `/ru/` по меню и главной (список URL уже собран), для каждого типа страницы сохраняет: заголовки, названия колонок таблиц, список фильтров, число строк. **Только структуру и счётчики**, не контент.
- Результат: `docs/site_spec.json` — эталон «что должно быть» и счётчики для приёмки.
- Уже сделано: обход 45 страниц (заголовки, колонки, счётчики), см. раздел 1.

### P1. Универсальный слой данных
- Загрузчик любой `.datc64` по схеме (`schema.min.json` + автогенерация колонок), с локализацией RU/EN (`datrows.table(name, lang)`).
- Построение **графа сущностей**: Item ↔ Mod ↔ Stat ↔ Tag, Gem ↔ GrantedEffect ↔ Level ↔ Stat, PassiveNode ↔ Stat ↔ Class, Monster ↔ Skill ↔ Area, Quest ↔ Reward ↔ Item, Area ↔ Boss ↔ Monster.
- Хранение: SQLite с нормализованными таблицами `entity_*` + `link(from,to,kind)`; полнотекстовый индекс FTS5 по RU/EN.
- Схемы таблиц, которые не читаются (`mods` дал «schema mismatch»), чиним сразу — это блокер раздела «Свойства».

### P2. Генератор раздела по описанию
Каждый раздел описывается маленьким файлом (YAML/JSON): таблицы, связи, колонки, фильтры, сортировка, шаблон карточки. Один рендерер строит:
- **список** (виртуальная таблица, фильтры, сортировка, быстрый поиск, подсветка, закладки);
- **карточку** (кросс-ссылки, всплывающая плашка при наведении, как у предметов);
- **калькулятор / сравнение** там, где сайт его даёт (вес свойств, уровни камней).

### P3. Спец-визуализаторы
- **Деревья** (пассивки, Атлас): раскладка узлов из таблиц + `PassiveSkillTreeUIArt` и рамки узлов; поиск, подсветка путей, подсчёт очков.
- **Карта локаций актов** и связей зон/боссов.
- **Таблицы рецептов** (перековка, крафт) как графы.

### P4. Наши преимущества (то, чего нет на сайте)
- 3D везде: предмет, монстр, NPC, умение, декор убежища.
- Анимации и звук привязаны к умениям и монстрам, эффекты удара.
- Редактор: надеть любой предмет/NPC, экспорт в Blender, запись с прозрачным фоном.
- Просмотр файлов игры (картинки, текстуры, модели, звуки) и поиск по всем 4 млн файлов.
- Сравнение версий игры (P6).

### P5. Поиск и связи
- Единый поиск по всему (предметы, свойства, умения, монстры, локации, квесты), RU/EN, с типами результатов и фильтрами.
- Обратные ссылки: «где встречается это свойство», «какие монстры бросают», «какие умения используют эту поддержку».

### P6. Версии и патчноуты
Патчноутов в файлах игры нет. Вместо них: хранить срезы таблиц по версиям (хэш + дифф) и показывать «что изменилось» по предметам, свойствам, умениям, монстрам. Это перекрывает `Version_0.5.x` и даёт больше сайта.

### P7. Контроль качества
- Автосверка со `site_spec.json`: число записей по разделам, список колонок.
- Выборочная сверка значений (случайные 50 записей на раздел) с сайтом вручную или полуавтоматически.
- Скриншот-тесты ключевых страниц, замер скорости (список 5000 строк < 300 мс).

## 4. Риски

- **Схемы таблиц** меняются между патчами (колонки смещаются): держим автоматический тест «парсер → разумные значения» на каждой таблице.
- **Объём**: 1023 таблицы + 4 млн файлов: индексы и кэш обязательны, вычисляемые страницы кэшируем.
- **Права**: нельзя копировать тексты и картинки сайта; используем данные игры (локально, как и сейчас) и свои тексты интерфейса.
- **Формулы** (например, расчёт веса свойств, шансов) на сайте часто выведены вручную — сверяем с игровыми таблицами, а не копируем.
